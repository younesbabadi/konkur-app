# حل‌یار — دستیار هوش مصنوعی کنکور — راهنمای نسخه‌ی انتشار

نسخه‌ی جدید حالا شامل **لاگین واقعی با موبایل**، **دیتابیس Postgres**، و **پرداخت اشتراک با زرین‌پال** هست.

## ساختار پروژه
```
konkur-app/
  server.js       ← سرور اصلی (API، احراز هویت، پرداخت)
  db.js           ← اتصال و اسکیمای دیتابیس Postgres
  sms.js          ← ارسال پیامک کد تایید (کاوه‌نگار)
  zarinpal.js      ← اتصال به درگاه زرین‌پال
  package.json
  .env.example
  index.html      ← لندینگ‌پیج
  app.html        ← خود اپلیکیشن
  README.md
```

## نحوه‌ی کار سیستم (مهم)
- هرکسی می‌تونه بدون هیچ ثبت‌نام یا واردشدنی مستقیم وارد اپ بشه و سوال بپرسه.
- سهمیه‌ی رایگان (پیش‌فرض ۸ سوال در روز) بر اساس IP کاربر شمرده می‌شه، نه حساب کاربری.
- وقتی سهمیه تموم بشه (یا کاربر خودش از تب اکانت بزنه رو «خرید اشتراک»)، تازه یه مودال باز می‌شه
  که شماره موبایل و کد تایید می‌گیره — این تنها جایی‌ه که لاگین لازم می‌شه، و بلافاصله بعدش
  کاربر می‌ره درگاه زرین‌پال.
- بعد از خرید موفق، توکن کاربر تو مرورگرش ذخیره می‌مونه و از اون به بعد سوالاتش نامحدوده.

## چیزهایی که قبل از انتشار باید تهیه کنی

### ۱. حساب Zarinpal (برای دریافت پول)
برو به [zarinpal.com](https://www.zarinpal.com) ثبت‌نام کن (نیاز به کد ملی/مدارک کسب‌وکار داره).
بعد از تایید، از پنل، **Merchant ID** رو بردار — این می‌شه `ZARINPAL_MERCHANT_ID`.
برای تست قبل از تایید نهایی، می‌تونی `ZARINPAL_SANDBOX=true` بذاری و کار کنی.

### ۲. حساب کاوه‌نگار (برای ارسال پیامک کد تایید)
برو به [kavenegar.com](https://kavenegar.com) ثبت‌نام کن، یه الگوی «Verify Lookup» با اسمی مثل `verify` بساز
(تو پنلشون بخش «الگوهای وریفای» هست)، و API Key رو بردار.

**نکته مهم:** اگه `KAVENEGAR_API_KEY` رو خالی بذاری، سرور کد تایید رو به‌جای پیامک واقعی تو
لاگ سرور (کنسول Railway) چاپ می‌کنه — این برای تست اولیه‌ی رایگان عالیه، ولی برای انتشار واقعی
حتماً باید این کلید رو ست کنی وگرنه کاربرا کدشونو نمی‌گیرن.

### ۳. دیتابیس Postgres
تو Railway: داخل همون پروژه، **New → Database → Add PostgreSQL** رو بزن.
Railway خودش متغیر `DATABASE_URL` رو می‌سازه و به سرویس اصلیت وصل می‌کنه — کافیه تو
تنظیمات سرویس اصلی، رفرنس بدی به دیتابیس (یا از Variable Reference استفاده کنی).

### ۴. متغیرهای محیطی روی Railway
تو تب Variables سرویس، این‌ها رو ست کن (طبق `.env.example`):
```
GEMINI_API_KEY=...
DATABASE_URL=...            ← از پلاگین Postgres میاد
JWT_SECRET=...               ← یه رشته‌ی تصادفی طولانی (با openssl rand -hex 32 بساز)
APP_BASE_URL=https://your-domain.up.railway.app
ZARINPAL_MERCHANT_ID=...
SUBSCRIPTION_PRICE_TOMAN=99000
KAVENEGAR_API_KEY=...
KAVENEGAR_TEMPLATE=verify
```

## تست لوکال
```
npm install
cp .env.example .env
# مقادیر .env رو پر کن (حداقل GEMINI_API_KEY و DATABASE_URL لازمه)
npm start
```
بدون `KAVENEGAR_API_KEY`، کد تایید تو ترمینال چاپ می‌شه — از همونجا کپی کن و وارد اپ کن.

## چیزهایی که هنوز نیستن (برای فازهای بعدی)
- تاریخچه‌ی چت‌ها هنوز رو `localStorage` مرورگره، نه سرور — یعنی با پاک‌شدن کش یا عوض‌کردن گوشی، از بین می‌ره.
  اگه بخوای بین دستگاه‌ها sync بشه، باید چت‌ها رو هم ببریم رو دیتابیس (قابل اضافه‌کردنه).
- پنل مدیریتی برای دیدن کاربرا/درآمد وجود نداره — فعلاً باید مستقیم از دیتابیس نگاه کنی.
- تمدید خودکار اشتراک (auto-renewal) نداره؛ هر ماه کاربر باید دستی دوباره بخره.
